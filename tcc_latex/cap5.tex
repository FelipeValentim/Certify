\chapter{Apresentação do Sistema}

\section{Tecnologias a serem usadas no Frontend}

O aplicativo foi desenvolvido em \textbf{React Native 0.74} com o runtime do \textbf{Expo SDK 51}, utilizando o modelo de componentes funcionais e API de Hooks do React. As principais bibliotecas adotadas são:

\begin{itemize}
    \item \textbf{@react-navigation/native + createNativeStackNavigator:} Controle da hierarquia de telas (pilhas pública e privada) e navegação programática entre rotas.
    \item \textbf{Redux Toolkit:} Gerência global de estado com dois \textit{slices}: \texttt{token.js} (sessão JWT) e \texttt{snackBar.js} (notificações de feedback global).
    \item \textbf{expo-secure-store:} Armazenamento criptografado do token JWT no cofre nativo do sistema operacional (\textit{Keychain} no iOS, \textit{KeyStore} no Android).
    \item \textbf{expo-camera (CameraView):} Captura de câmera nativa para leitura de QR Code com validação por \texttt{boundingBox}.
    \item \textbf{react-native-gesture-handler (Swipeable):} Gestos de deslizamento horizontal em cards da lista de eventos e convidados.
    \item \textbf{react-native-draggable-flatlist:} Lista com suporte a reordenação por arrastar-e-soltar (\textit{Drag 'n Drop}) a 60fps.
    \item \textbf{react-native-paper:} Componentes visuais baseados em \textit{Material Design} (inputs, dialogs, FAB).
    \item \textbf{expo-font (Poppins):} Família tipográfica carregada assincronamente na inicialização (Regular, Bold, Black, ExtraBold).
    \item \textbf{expo-image-picker:} Seleção e compressão de fotos da galeria ou câmera.
    \item \textbf{expo-document-picker + expo-file-system:} Seleção de arquivos \texttt{.docx} e leitura em Base64 para upload do template de certificado.
    \item \textbf{react-native-webview:} Renderização do PDF de pré-visualização do certificado diretamente no aplicativo.
    \item \textbf{Axios:} Cliente HTTP com interceptors que injetam automaticamente o cabeçalho \texttt{Authorization: Bearer \{token\}} em todas as requisições autenticadas.
    \item \textbf{@fortawesome/react-native-fontawesome:} Ícones vetoriais (lixeira, chevron, check, refresh, etc.).
    \item \textbf{date-fns:} Utilitário de formatação de datas no frontend (ex: \texttt{format(date, "dd/MM/yyyy")}).
\end{itemize}

Em caso de sucesso, o token JWT é persistido via \texttt{expo-secure-store} e a \textit{Redux Store} é atualizada com \texttt{dispatch(signIn(token))}, o que dispara a remontagem reativa da pilha de navegação para a pilha privada (Home).

A tela Home lista exclusivamente os eventos do organizador autenticado, cujo UUID é extraído do token JWT pelo \texttt{UserContextService} no backend. Os filtros de status são aplicados em memória no frontend (\texttt{filter()} sobre o array \texttt{events}), evitando chamadas redundantes ao servidor. O gesto de \textit{swipe} para a esquerda é gerenciado pelo componente \texttt{Swipeable} da biblioteca \textit{react-native-gesture-handler}, que expõe o botão de exclusão com abertura de modal de confirmação (\texttt{ConfirmAlert}).

O organizador pode alterar o modo de check-in via modal, que aciona o endpoint \texttt{PUT /Event/CheckinEnabledMode}, persistindo o valor \texttt{null} (Automático), \texttt{true} (Ativado) ou \texttt{false} (Desativado) no campo \texttt{CheckinEnabled} da tabela \texttt{Event}.

A tela de scanner maximiza a área útil do visor ao remover o cabeçalho padrão. A animação das bordas de mira é implementada com \texttt{Animated.loop + Animated.sequence}, expandindo e contraindo suavemente os cantos entre 1000ms cada ciclo via \texttt{useNativeDriver: false}. A leitura é considerada válida apenas se o \texttt{boundingBox} do código QR detectado estiver dentro dos limites do quadro de mira (\texttt{scannerBounds}), evitando leituras acidentais de códigos fora do enquadramento.

A aba de convidados é a mais complexa do sistema. O modo de seleção em massa é ativado com \texttt{onLongPress} (400ms), que adiciona o item ao array \texttt{selectedItems} e substitui o cabeçalho padrão pelo \texttt{SelectionHeader}. Os dois filtros \texttt{SegmentedControl} (status e tipo) operam em memória sobre o array \texttt{guests} sem requisições adicionais. O menu de contexto (\texttt{PopupMenu}) acionado pelo botão de três pontos oferece as ações em lote: \textit{Enviar certificado} (para selecionados com check-in) e \textit{Enviar convite} (para selecionados sem check-in), além de exclusão e inversão de check-in.

O upload do template lê o arquivo selecionado como Base64 via \texttt{FileSystem.readAsStringAsync(uri, \{ encoding: EncodingType.Base64 \})} e envia para \texttt{POST /EventTemplate/Upload/\{eventId\}}. O backend valida o tipo MIME, o tamanho máximo (10 MB) e a presença obrigatória do \textit{placeholder} \texttt{\{Nome\}} utilizando a biblioteca \texttt{Xceed.Words.NET} antes de aceitar o arquivo. Após aprovação, ambos o \texttt{.docx} original e a pré-visualização \texttt{.pdf} são gravados no \texttt{StorageService} e seus caminhos persistidos na tabela \texttt{EventTemplate}.
